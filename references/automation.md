# Автоматизация в версии 1.1

## Что включено

- `scripts/pnl.mjs` — расчёт по подготовленным месячным данным и сравнение версий. Только стандартные модули Node.js; проверено на Node.js 24.19.0.
- `scripts/build-workbook.mjs` — создание XLSX средствами `@oai/artifact-tool` из среды Codex. Это отдельная зависимость; сам расчётный модуль её не требует.
- `examples/demo.json` — вымышленные данные двух площадок за январь–март 2026 года, факт и бюджет.
- `examples/expected.json` — независимые контрольные суммы, рассчитанные вручную.
- `examples/pnl-demo.xlsx` — заполненная демонстрация.
- `assets/pnl-template.xlsx` — пустая книга того же формата, неизвестные суммы дают «н/д».
- `assets/input-template.json` — незаполненный профиль. До указания источников и баз он намеренно не проходит проверки.
- `tests/pnl.test.mjs` — исполняемые проверки логики и ошибок.

## Команды

Выполняй из каталога навыка. Путь результата должен указывать в отдельную рабочую папку; родительская папка для JSON уже должна существовать.

```sh
node --test tests/pnl.test.mjs
node scripts/pnl.mjs calculate examples/demo.json /path/to/work/report-v1.json
node scripts/pnl.mjs compare /path/to/work/report-v1.json /path/to/work/report-v2.json
node scripts/build-workbook.mjs examples/demo.json /path/to/work/demo.xlsx
node scripts/build-workbook.mjs examples/demo.json /path/to/work/template.xlsx --blank
```

`calculate` не перезаписывает существующий файл, не меняет вход и не добавляет строки к предыдущему результату. Код выхода: 0 — рассчитан или предварительный (смотри `status` и `issues`), 2 — некорректные/неполные данные с сохранённой диагностикой, 1 — ошибка запуска/формата/записи. Хеш исходного файла находится в `input_sha256`. `compare` печатает изменения итоговых показателей по месяцу/сценарию, не вычисляет причины и не сравнивает карточки источников.

Генератор требует доступный пакет `@oai/artifact-tool`; используй инструкции установленного навыка таблиц и предоставленный runtime. Не обещай воспроизводимость генерации на компьютере без этого пакета. Готовый XLSX можно использовать в Excel без Node.js и этого пакета. `build-workbook.mjs` перезаписывает указанный выходной XLSX при повторной сборке — выбирай путь осознанно. `PNL_PREVIEW_DIR` — необязательная папка рендеров для проверки.

## Контракт месячных данных v1

Верхний уровень:

- `schema_version: 1`, `currency: "RUB"`, `unit: 1`, `basis: "accrual"`, `vat: "excluded"`.
- `periods`: уникальные месяцы `YYYY-MM` в нужном хронологическом порядке.
- `sites`: уникальные коды площадок; зарезервированы `CENTER`, `ELIM`, `TOTAL`.
- `scenarios`: уникальные значения `actual`, `budget`, `forecast`.
- `records`: ровно одна месячная строка на сочетание период × сценарий × объект. Кроме площадок обязательны `CENTER` и `ELIM`.
- `allocations`: одна запись на период × сценарий: `period`, `scenario`, `bases` с неотрицательной числовой базой каждой площадки.

Одна строка `records` содержит уникальные `id` и `source_ref`, ключи `period`, `scenario`, `scope`, булев `closed` и все денежные поля ниже. `source_ref` ссылается на уникальную строку или агрегат источника, например `export-id:row-id`; одинаковый файл допустим, одинаковая строка-источник дважды — нет. Это месячные снимки, не проводки: несколько операций нужно сначала обоснованно агрегировать, сохранив внешний реестр детализации. Корректировки включаются в новый снимок один раз, повторные выгрузки не складываются.

| Поле | Значение |
|---|---|
| revenue | Признанная выручка |
| cogs | Себестоимость проданного |
| selling, admin | Коммерческие и управленческие расходы |
| other_income, other_expense | Прочие операционные доходы и расходы |
| da | Амортизация, уже включённая в расходы этого P&L; справочно для EBITDA |
| financial_income, financial_expense | Доходы/расходы моста от EBIT к прибыли до налога |
| tax | Налоговый расход по согласованной методике |

Суммы — числа в рублях до двух знаков после запятой, абсолютная величина не более 1 млрд рублей на поле. Неизвестная сумма — `null`; отсутствие операций — подтверждённый `0`. Расходы положительные, сторно и элиминации имеют свой знак. Валюта и масштаб уже приведены к контракту, возмещаемый НДС исключён на этапе подготовки. До 1000 месячных строк на запуск; это ограниченный проверочный модуль, не универсальная система консолидации.

`CENTER.admin` — единственный распределяемый пул версии 1.1, остальные расходы центра остаются там. Пул должен быть неотрицательным. Входные расходы площадок ещё не включают это распределение. При нулевых базах пул остаётся в центре; при отсутствующих/отрицательных базах расчёт не считается полным. Копейки распределяются по накопленной доле в порядке `sites`, чтобы сумма точно совпадала с пулом.

`ELIM` — подготовленные и отдельно обоснованные поправки по статьям. Нулевые значения означают подтверждённое отсутствие поправок. Модуль не устанавливает сам наличие внутренних продаж и не рассчитывает нереализованную прибыль: это делает аналитик по источникам до запуска. Для каждой поправки нужен внешний реестр основания, который остаётся в закрытом проекте.

## Границы XLSX

Генератор рассчитан на две площадки, обязательные факт и бюджет и произвольный заданный набор месяцев в пределах ограничения. Он создаёт пять листов: P&L, данные, распределение, расчёт по объектам, проверки. Полный P&L за период и месячные ключевые показатели доступны на первом листе.

Менять в готовой книге можно суммы, базы, ссылки на источники и признак закрытия. Не переименовывай ключи, не сортируй и не добавляй строки вручную: для изменения структуры обнови JSON и пересоздай книгу. Сохранение правок XLSX обратно в JSON не реализовано; при регулярном процессе храни первичные данные отдельно и используй один выбранный источник истины.

В книге видны проверки наличия сумм, закрытия, источников и распределений. Наличие источника не подтверждает его достоверность. Проверки JSON выявляют дубли/неизвестные поля до генерации; повторяй их при новом импорте. Нативный Excel был проверен на демонстрации и пустом шаблоне версии 1.1, но неизвестные будущие файлы требуют своей проверки.

## Частный профиль и 1С

Копируй шаблон в рабочую папку вне публичного репозитория. Реальные названия, статьи, политики, маппинг и файлы источников остаются там. Образец `demo.json` не является маппингом 1С: его надо построить по фактическим выгрузкам и проверенным настройкам. Автоматический импорт произвольных выгрузок 1С и соединение с базой в версии 1.1 отсутствуют.
