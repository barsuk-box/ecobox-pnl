# ecobox-pnl

Авторский навык Codex для создания управленческого отчёта о прибылях и убытках производственного бизнеса. Подходит для одной или нескольких площадок, Excel/Google Sheets и подготовки данных из 1С.

## Возможности

- Помесячный P&L по производствам и сводно, план-факт и прогноз.
- Себестоимость проданного, НЗП, готовая продукция и защита от повторного счёта затрат.
- Общие расходы, корпоративный центр и элиминация внутренних операций.
- EBIT, EBITDA, прибыль и рентабельность с явными правилами расчёта.
- Маппинг статей, трассировка, сверки и реестр недостающих данных.
- Паспорт методики и десять контрольных ситуаций с ожидаемым результатом.

Это пакет инструкций с вспомогательными расчётами и шаблонами. Он не подключается к 1С и не содержит финансовых данных компании, готового фактического отчёта, налоговых ставок или утверждённой корпоративной учётной политики. Все числовые примеры вымышлены.

Модуль расчёта использует только Node.js; для пересоздания XLSX генератором нужен `@oai/artifact-tool` из среды Codex. Автоматический импорт конкретных выгрузок 1С потребует отдельного маппинга.

## Установка в Codex

Попросите встроенный установщик:

```text
Используй skill-installer: установи скилл из https://github.com/barsuk-box/ecobox-pnl
```

Либо склонируйте репозиторий и скопируйте `SKILL.md`, `LICENSE`, папки `agents`, `references`, `assets`, `scripts`, `examples` и `tests` в отдельный каталог `ecobox-pnl` внутри пользовательского каталога навыков вашей версии Codex. Не заменяйте существующий навык без просмотра изменений. В окружении, где применим `$CODEX_HOME/skills`, используйте его, а при отсутствии этой переменной — `~/.codex/skills`. Если навык не появился, начните новую сессию или перезапустите приложение.

Расположение каталога может зависеть от версии клиента: [официальная документация навыков](https://developers.openai.com/es-419/docs/build-skills).

## Использование

```text
Используй $ecobox-pnl. Подготовь шаблон P&L для двух производств:
помесячно, отдельно и сводно, с план-фактом. Данных пока нет.
Сначала составь паспорт методики и список необходимых выгрузок.
```

```text
Используй $ecobox-pnl и Spreadsheets. По приложенным выгрузкам
создай Excel с P&L, правилами распределения и листом сверки.
Неизвестные суммы не считай нулевыми. Покажи нерешённые расхождения.
```

```text
Используй $ecobox-pnl. Проверь существующий отчёт:
нет ли двойного счёта себестоимости, ошибки EBITDA,
неисключённых внутренних продаж и неверной итоговой маржи.
```

Для первого фактического отчёта нужны период, периметр, методика и выгрузки, перечисленные в [подготовке данных 1С](references/1c-inputs.md). Банковская выписка сама по себе недостаточна.

## Совместимость и ограничения

Инструкции навыка не требуют runtime. Для дополнительных расчётных команд нужен Node.js, проверено на 24.19.0. Генератор и пересчёт XLSX требуют доступного инструмента работы с таблицами; для Google Sheets нужен соответствующий доступ. Подключение к базе и проверка конкретного релиза 1С выполняются отдельно. Доступные `financial-analyst`, `cfo-advisor` и Spreadsheets можно использовать совместно, но они не включены в пакет и не обязательны для чтения методики.

Навык предназначен для управленческого анализа. Правила регламентированной отчётности и налогообложения проверяются отдельно. MIT-лицензия не означает аудиторскую проверку результатов.

## Проверка и развитие

Структуру можно проверить штатным `quick_validate.py` из `skill-creator`, передав путь к этому каталогу. [Контрольные сценарии](references/acceptance.md) предназначены для проверки качества расчётов и поведения агента. Структурная проверка не заменяет пробный отчёт на реальных обезличенных данных и проверку формул в целевой программе.

Исполняемые тесты: `node --test tests/pnl.test.mjs`. На демонстрации проверены полный расчёт, экспорт и пересчёт книги в Artifact Tool и нативном Excel 16.0, изменение выручки, отсутствующая себестоимость, нулевые базы и заполнение пустого шаблона. Подробности: [проверка версии 1.1](references/validation-1.1.md). Реальные данные компании не использовались; качество произвольной выгрузки этим не подтверждается.

Приватные данные для испытаний храните вне репозитория. В PR включайте обезличенный или вымышленный пример, ожидаемое поведение и конкретное изменение правил.
